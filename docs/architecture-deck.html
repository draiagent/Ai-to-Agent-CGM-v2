04 / 12
Layer 1

輸入層 · 三軌

軌 A飲食影像

手機拍照 → ML Kit 裝置端前處理 → Google Drive 指定資料夾；或 LINE／Telegram Bot 傳送。必留時間戳 T0（對齊錨點）。

軌 A情境備註 高槓桿

文字或語音：「半糖」「約半碗飯」「先菜後飯」「飯後散步 15 分」。可把 15–30% 的份量誤差顯著拉低。

軌 BCGM 血糖 選型待定

Dexcom 官方 API（OAuth）；Abbott Libre 無官方 API，走 LibreLinkUp 或 CSV 匯出。此選型決定自動化程度。

軌 C情境訊號（可選、輕量）

睡眠時數、主觀壓力、HRV、餐後活動 —— 一鍵手動標記或串接裝置，餵給 L4 做干擾校正。

05 / 12
Google ML Kit

ML Kit 的職責界線

ML Kit 沒有食物辨識 API。它在裝置端「把照片處理乾淨、把文字讀出來」；食物品項與份量仍由雲端多模態 LLM 負責。

ML Kit API本系統角色執行位置
Document Scanner拍照自動偵測邊界、裁切、去傾斜、畫質增強裝置端
Text Recognition v2OCR：讀包裝營養標示、菜單、外送明細裝置端
GenAI（Gemini Nano）語音備註轉文字；影像粗描述做預先分類裝置端
Image Labeling（自訂 TFLite）進階：訓練「個人常吃食物」輕量模型，減少雲端呼叫裝置端
分工：ML Kit 裝置端前處理／OCR → 雲端 LLM 食物辨識與份量 → 營養／GI 資料庫給數字。
06 / 12
Layer 2

運算層 · 多模態 AI Agent

五步驟

  • ① 食物辨識、品項對應
  • ② 份量估算（推估值，附誤差區間）
  • ③ 解析情境備註 → 修正含糖／烹調／份量假設
  • ④ 向 TFDA／USDA FDC 對齊營養數字，向 GI 資料庫 查 GI／GL
  • ⑤ 使用者一鍵確認／微調 → 可回溯重算

用詞修正（重要）

  • 「精準估算」→「推估」：2D 影像對隱藏油脂／勾芡／糖分有 15–30% 天然誤差
  • GI 不是能「算」的，是查標準資料庫；混合菜色以成分加權並標低信心
  • 模型不自行生成營養數字，全部來自資料庫，帶出處與信心度

Layer 3

儲存層 · Google Sheets（原型）

單人多年沒問題：CGM 每 5 分鐘 = 288 筆／日 ≈ 10.5 萬 筆／年，遠低於單檔上限。多人則換 Postgres／BigQuery／InfluxDB。

飲食紀錄表

meal_id(PK) · t0 · note · items_json · 五大營養素 · gi_est/gl_est · eating_order · post_meal_activity · confidence · user_confirmed

CGM 血糖序列表

ts(PK) · glucose_mgdl（全專案統一 mg/dL）· sensor_session · source

情境標記表

date · sleep_hours · stress_subjective · hrv · notes

  • 入口一律轉 Asia/Taipei；以 ts + sensor_session 去重；離群值與斷點標記。
  • 時間戳為三表 join key。

Layer 4 · 指標

時間軸對齊 · 五指標

以 T0 為錨，取餐後 0–180 分鐘血糖窗。每個指標都在 spec 裡寫死定義。

指標定義與判讀
餐前基準[T0−15min, T0] 血糖平均
ΔPeak窗內最大值 − 基準　→　單餐血糖衝擊大小
達峰時間快 30–45min → 高 GI／精緻澱粉／液態糖；慢 60–90min+ → 高油脂／蛋白／複合澱粉，胃排空慢
iAUC梯形法，基準以下截 0，mg/dL·min　→　整體葡萄糖暴露量
恢復時間回「基準 +10 mg/dL」內且持續 N 分鐘　→　反映胰島素敏感度

CGM 相對血糖有 5–15 分鐘生理延遲，報告須註明。

09 / 12
Layer 4 · 干擾校正

碳水總量 ≠ 血糖反應

關聯性分析必須同步納入下列干擾變數，否則排行榜不可信。

餐次隔離

前 3h／後 2h 內有其他進食 → 排除或標低信心

餐食組合與進食順序

先菜／蛋白質、足量纖維與健康脂肪 → 延緩胃排空、壓平峰值

餐後活動 · GLUT4

散步 10–15 分／節拍超慢跑 → 骨骼肌非胰島素依賴途徑吸收葡萄糖，峰值大幅下降

睡眠 / 壓力 / 自律神經

睡眠不足或交感高張（HRV 偏低）→ 皮質醇上升，同等碳水波動更劇烈

個人腸道菌 / 代謝差異

同食物在不同個體反應可能截然不同 → 結論只對本人有效

規律歸納門檻

同一食物／情境組合需 ≥3 次重複曝光才納入結論，呈現 mean ± SD

Layer 5

輸出層

個人化食物反應圖譜

以「每 15g 碳水的 ΔPeak」或 iAUC / 可利用碳水 標準化排行，否則排的是份量不是食物。

「意外峰值」清單 核心價值

揪出引發超出預期血糖衝擊的食物／情境組合 —— 這是系統存在的理由。

血糖反應彈性趨勢

CGM 代理指標（非嚴格代謝彈性）：CV、MAGE、SD、TIR、隔夜穩定度、餐後恢復速度。

行動建議

調整進食順序、餐後散步、特定食物替換 —— 對應到可執行的生活型態改變。

＋ 醫療免責聲明與個資治理：非醫療建議；健康資料依個資法處理，涉及他人需同意書。

Reference Databases

參考資料庫

升糖指數 GI／GL

  • University of Sydney Glycemic Index Database（glycemicindex.com）
  • International Tables of Glycemic Index and Glycemic Load（Atkinson 等，Diabetes Care）—— 含 GL，適合離線對照

食物營養成分

  • 衛福部 TFDA 食品營養成分資料庫 —— 本土菜色首選
  • USDA FoodData Central（FDC）—— 國際品項、加工食品，有 API
  • 包裝食品營養標示（OCR 擷取）—— 現場最準，優先採用
實作：離線建 GI 對照表 ＋ 呼叫 FDC API ＋ 快取 TFDA 匯出；Agent 只做「辨識 → 對應品項 → 帶份量查表」。
